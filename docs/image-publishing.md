# 视频与图文发布

## 网页

打开“发布”，目前接入小红书：

1. 选择“视频”或“图文”。
2. 视频选择一个 MP4；图文选择 PNG、JPEG 或 WebP，可增补、移除和调整图片顺序。
3. 填写标题、正文、话题，以及可选的北京时间排期。
4. 点“保存到发布计划”：素材保存在配置的 rootPath，创建计划和文案快照，不访问小红书。
5. 在工程详情点“填写小红书（不发布）”，确认后才上传、填写。
6. 在专用 Chrome 核对内容、图片顺序、原创声明和定时，自己点最终发布。

网页创建工程限制为单个视频不超过1GB，图文1–18张、单张不超过20MB；这是本工具的保守限制，不代表平台官方上限。现有视频多平台命令保持不变，不新增1GB限制；其他平台的图文尚未接入。

需要 direct 驱动和已安装的发布助手。图文适配器在本仓库 `src/xhs-images.mjs`，不会修改商店插件文件，不会被插件自动升级覆盖。开发桥模式暂不支持图文。

## 工程格式

旧工程没有 `mediaType` 时默认视频。图文明确写 `mediaType: "images"`，`images` 按最终展示顺序排列，路径相对工程目录：

```json
{
  "version": 1,
  "id": "CC-YYYYMM-NNN-xhs-images-v1",
  "name": "本期主题",
  "mediaType": "images",
  "video": null,
  "images": ["图片/01.png", "图片/02.png"],
  "covers": {},
  "requiredTags": [],
  "platforms": {
    "xhs": {
      "title": "本期标题",
      "body": "本期正文",
      "topics": ["主题"],
      "covers": []
    }
  }
}
```

视频使用 `mediaType: "video"` 和 `video: "成片.mp4"`，不填写 images。小红书图文仍沿用已安装插件的标题、正文、链接和话题校验规则。图片路径不允许绝对路径、父级路径、重复项或指向工程外的符号链接。

## Agent 与命令行

把图片放到工程目录的 `图片/` 内，按展示顺序命名 `01.png`、`02.png`。发布素材：

```markdown
# 本期主题

> 发布类型：图文

## 四、小红书
**标题：**
本期标题
**正文：**
本期正文
#主题
```

```bash
node src/make-publish.mjs "<发布素材.md>" "<工程目录>" --type images
node src/validate.mjs "<工程目录>"
node src/hub.mjs plan "<工程目录>"
node src/hub.mjs run "<工程目录>" --only xhs
```

`--type video` / `--type images` 优先于 Markdown 的 `> 发布类型：视频/图文`；两者都没有时仍默认视频。图文生成器按文件名自然排序，执行前必须检查 JSON 中的 images 顺序；网页上传的文件使用内部唯一名称并按用户排列保存，不依赖文件名排序。

## 安全与排错

- 保存计划不是上传授权，网页保存后不会开始填写。
- 已填好、待发布、已定时和已发布任务不允许再次点击填写；失败重试前先人工检查平台草稿，不能盲目重传。
- 图片上传完成后核对数量、标题、正文和话题；数量或正文不一致会停止并报错，不自动提交。首图即图文第一张；不会运行视频封面裁剪流程。
- 该适配器依赖创作者后台 DOM。平台改版可能导致元素或数量核对失败，需要重新适配；单元测试和本地界面测试不能代替真实平台验收。
- X Article 仍是不同形式，没有因新增小红书图文而自动支持。`archive.mode: "archive_only"` 的历史存档仍禁止执行，不能删除 skip 后当新稿发布。
- 上传中的文件临时保存在 `rootPath/.publish-drafts/`，不参与自动扫描；失败的完整草稿暂留供排错，成功后移入独立工程目录。源文件不改动。每次保存新工程使用唯一 id，重复发布防重以该工程任务状态为准，不能靠新建另一个 id 绕过防重。

## 验证范围

自动测试覆盖工程生成、图文/视频分流、素材路径及类型、鉴权、跨站请求阻止、图片排序、计划保存、已填任务防重和图文适配器的停止条件。开发验证不上传真实内容、不点发布；首次实际使用需由用户监督核对平台页面。
