## 先理解部署边界

当前系统是单用户、本地文件和本地 Chrome 驱动的工具，不是成熟的多租户 SaaS。
网页后台与右侧插件是两条独立入口，安装插件不会自动配置网页或同步两者的运行记录。

推荐先作为独立服务接入现有平台导航，保留本地执行端；再根据实际平台架构拆分任务服务和执行器。
平台服务器负责用户、内容、授权和任务，本地执行器负责读取已授权素材、使用对应账号的 Chrome 填写。
仅嵌入网页或迁移前端不能让服务器访问用户电脑的文件或浏览器登录态。

## 本地启动

运行环境使用 Node.js 24（项目声明最低 22.5）、Chrome；视频时长检测需要 `ffprobe`。
主体使用 Node 内置模块，没有需要安装的 npm 运行依赖。浏览器执行还依赖发布助手模块，按主 README 和插件说明配置，不能仅启动 HTTP 服务就视为完成安装。

```bash
node src/init.mjs
node src/hub.mjs daemon
```

安装向导会创建本机 `config.json`。无口令的本机网页配置：

```json
{
  "web": { "port": 8787, "host": "127.0.0.1", "key": "" }
}
```

将此片段合并到实际配置，不要用它替换完整配置。`rootPath` 必须指向真实存在、可写的发布工程目录。
上述配置仅用于本机，不可加公网隧道或直接复用到线上。配置、素材、账号登录态和 SQLite 数据不随仓库交付。
通过 `MAITIAN_CONFIG` 和 `MAITIAN_DB` 可指定配置及数据库路径。

## 网页发布接口

接口仍受 `src/web.mjs` 的现有鉴权控制，不是无鉴权公共 API。
同源 JSON 操作使用 `Content-Type: application/json`；跨站调用受限制，需要平台后端适配，不能直接从另一域名调用。

| 请求 | 用途与关键参数 |
| --- | --- |
| `POST /api/publish-drafts` | 创建草稿，`{"mediaType":"images"}` 或 `"video"`；返回草稿 `id` |
| `POST /api/publish-drafts/:id/assets?name=01.png` | 上传单个二进制文件，类型 `application/octet-stream`，需要正确 `Content-Length`；返回素材 `file` |
| `POST /api/publish-drafts/:id/prepare` | 保存计划；传 `title`、`body`、`topics`、按顺序排列的 `assets`（上一步返回的 `file`），可选 `schedule` |
| `GET /api/state` | 当前工程、任务等状态，包含本机路径等信息，不能直接对外暴露 |
| `POST /api/action` | 明确授权后传 `{"type":"fill-xhs","id":"工程id"}`，开始填写；不是保存计划的自动后续步骤 |

`schedule` 使用 `YYYY-MM-DDTHH:mm`，按北京时间处理。
保存计划会创建本地工程和数据库任务，不上传到小红书。
图文只支持小红书，1–18 张 PNG/JPEG/WebP、单张最多 20MB；网页视频只收单个 MP4、最大 1GB。
这些是工具限制，不代表平台官方限制。

## 平台整合前必须补齐

- 复用现有平台登录与服务端权限校验；不能把空 key 配置暴露到公网。
- 按用户隔离素材目录、数据库任务、浏览器 profile、平台账号和密钥。目前不是多租户隔离实现。
- 任务队列、并发锁、幂等与审计，尤其检查重试前平台是否已有草稿或作品。不能靠新建工程 id 绕过防重。
- 素材访问授权、配额、大小限制、文件类型检查、临时文件清理和备份策略。
- 若接反向代理，验证 Origin、Host、转发头及上传体大小与超时，不盲目放开跨域。
- 前端展示“平台状态”和“素材准备状态”两个维度，不从全局存档状态推断所有平台已发布。
- 本地执行端的安装、升级和任务授权链路；CDP 调试端口只能供可信本机进程访问。

新小红书图文流程只填写，最终由用户手动确认发布。但原项目其他平台和命令存在自动提交逻辑，不能向用户承诺整个系统都绝不自动发布；上线前按目标平台逐一审查。
保留仓库根 MIT 许可证，以及侧栏插件目录内的 Apache-2.0 许可证。
